## 2. Исправленные технические неточности и сломанный код

1. **Лабораторная работа по FGSM (Фаза 5):**
   - *Было в v2:* обрывок кода с закомментированными строками `# x_test_adv = attack.generate(x=x_test)`, где переменная `x_test` вообще не была определена — скрипт нельзя было запустить.
   - *Стало в v3:* полностью рабочий автономный скрипт `fgsm_lab.py` на PyTorch + встроенном датасете `load_digits` (работает без интернета за 5 секунд!), который реально обучает модель, атакует её методом FGSM (точность падает с **97.6%** до **0.7%**) и защищает через **Adversarial Training** (точность восстанавливается до **81.7%**).
2. **Лабораторная по Data Poisoning / Backdoor (Фаза 5):**
   - *Было в v2:* искусственный пример на 150 строках Iris с числом `99.9`.
   - *Стало в v3:* реалистичный бэкдор `backdoor_lab.py` по идее научной статьи *BadNets* (визуальный штамп 2×2 пикселя в углу изображения цифры + детектор аномалий защитника).
3. **Уязвимость цепочки поставок Pickle (`.pkl`):**
   - *Было в v2:* упоминание только на словах.
   - *Стало в v3:* безопасная живая демонстрация `pickle_demo.py`, показывающая, как метод `__reduce__` выполняет код прямо в момент `pickle.loads()`, и почему индустрия перешла на `safetensors`.
4. **Мини-проекты на Python (Фаза 2):**
   - Вместо учебного брутфорсера SSH по списку паролей сделан защитный инструмент проверки паролей по базе утечек *Have I Been Pwned* через криптографический метод **k-anonymity** (первые 5 символов SHA-1 хэша).
   - В анализатор логов `log_analyzer.py` добавлено **двойное URL-декодирование (`unquote_plus`)** — без него реальные атаки в логах (`%3Cscript%3E`) остаются невидимыми.
   - В аудитор заголовков `headers_audit.py` добавлена проверка флагов `HttpOnly`, `Secure` и `SameSite` у `Set-Cookie`.
   - В Фазу 4 добавлен **полный рабочий код мини-RAG с нуля** на `requests` + `numpy` + `Ollama` (35 строк без тяжёлых фреймворков) с практическим экспериментом по Indirect Prompt Injection.
5. **Точные формулировки по сетям и криптографии:**
   - Чётко разделены **Кодирование (Base64) ≠ Хэширование (SHA-256 / Argon2) ≠ Шифрование (AES / TLS)**.
   - Уточнена механика **CORS**: почему браузер сам блокирует `*` вместе с куками, и почему настоящая опасность — это отражение `Origin` с `Access-Control-Allow-Credentials: true`.
   - Добавлена архитектура **JWT** (`header.payload.signature`) и объяснение, почему обычный JWT **подписан, но не зашифрован** (его содержимое может прочитать любой).
